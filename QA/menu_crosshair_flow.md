# 2026-11-01 菜单、准星与数据流修复

## 原因与复现

旧版在纯场景模式下的 `AEmberSuperParkController::Click` 跳过整个 HUD 点击分派。Esc 菜单仍正常绘制，因此按钮有悬停效果但不能继续或退出。

通过 Windows 窗口自动化实际点击旧版菜单中的“继续演示”和“退出超级园区”，两次截图均仍停留在暂停菜单，复现用户症状。反馈操作为 `sky.click` 后立刻 `sky.get_window_state`；未仅调用绕过点击路径的 Action 函数。

## 修复

- 暂停菜单在纯场景和管理台模式均优先接收 HUD 点击。
- 第一人称纯场景使用固定中央十字准星和直接鼠标转向；左键与 E 使用同一条摄像机射线，交互距离 4 米。
- 打开菜单释放鼠标，继续后恢复第一人称捕获；俯瞰和管理台保留指针与右键转向。
- 数据流独立使用半透明材质，连线不透明度 0.35，光点 0.60；不修改任何实际灯具材质。移动设备连线也使用该材质。
- N 与中枢 network.overlay 同时控制连线、光点和节点标签，不再留下延时消失的调试标签。
- 网页设备线、移动线与光点同步降低不透明度。

## 已完成检查

- Editor 构建通过，网页 Vite 构建通过。
- 新版实际窗口：F2 出现居中十字；不按右键的鼠标移动改变视角。
- 纯场景 Esc → 点击继续：菜单关闭、十字准星恢复。
- F10 管理台 Esc → 点击继续：菜单关闭、管理台指针模式恢复。
- N 隐藏所有设备线和光点，第二次 N 恢复为青色半透明显示。
- 回到纯场景后 Esc → 点击退出：日志记录 `UGameEngine::HandleExitCommand` 与退出状态 0。
